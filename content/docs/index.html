I wrote it in Rust with [MiniJinja](https://docs.rs/minijinja/latest/minijinja/syntax/index.html) providing the horsepower (MiniJinja being the Rust version of [Jinja](https://jinja.palletsprojects.com/en/stable/)). The implementation is based of dozens of prior iterations built over the past several years. The overall goal is to remove as much friction as possible from making web pages. And, not just blog posts, but pages with any given structure or content. The three keys that support that are: 1. All content files are templates with the full range of MiniJinja features available for processing. Each one can output directly or be used as an include in another file. 2. A global `d` variable is available in each template that contains the metadata from every content file as well as the data from every `.json` file on the site. 3. TODO: Images don't require paths. They can be stored anywhere in the content tree and accessed with their filename alone. ## Content Processing - Every file in the content tree can be used as a template that can be processed to generate its output. This allows the use of all MiniJinja logic, filters, and functions inside each content file. - Every file is available to be included in other templates. - Files with `.html`, `.js`, and `.txt` are passed through the transformation engine by default. - TODO: If an `.html`, `.js`, or `.txt` file has `.off` in its file name then it's copied directly without going through the transformation engine. - Files with other extensions are copied without transformation by default. - Files and with `.inc` in their names are available to be included but are not copied to the output tree. - TODO: Neopolitan files (i.e. `.neo` files) pass through the Neopoligen engine then the MiniJinja engine before being sent to the output tree as `.html` files. - TODO: Each file can contain an `id` value defined in its metadata. Other pages can use the id in `link(ID)` functions to automatically create a link to the page with its title and a URL that points to the page regardless of where it's moved. ## Templates - The default MiniJinja tags are converted to make them easier to read/scan: `{% %}` becomes `[! raw !][! !][! endraw !]` `{{ }}` becomes `[! raw !][@ @][! endraw !]` `{# #}` becomes `[! raw !][# #][! endraw !]` - MiniJinja line statements are enabled with `==` used as the token. For example, instead of creating a block with: [@ "" @][! raw !][! block main !] content [! endblock !][! endraw !] I can do: [@ "" @][! raw !]== block main content == endblock [! endraw !] which is much nicer to look at. ## Global Data - All .json files are available in the global `d` variable inside each template. For example, give a JSON file at: /path/to/data.json with the content: { "alfa": "bravo" } Doing this: [@ "" @][! raw !][@ d.path.to.data.alfa @][! endraw !][@ "" @] Outputs: bravo - The global data can be used inside control flows inside any content file. [!endraw!][@""@] - The metadata from each page is available in the global `d` variable as well (see below): ## Page Metadata Access - Page metadata is stored in [TMOL](https://toml.io/en/) format. - The metadata is stored inside a `toml` block. e.g. [@ "" @][! raw !]== block toml title = "page title" == endblock[! endraw !][@ "" @] This block can be stored anywhere in the content file. - The metadata for each page is added to the global `d` variable. For example, the `title` key from the toml metadata in the file: /some/content/file.html is available in: [@""@][!raw!][@ d.some.content.file.title @][!endraw!][@""@] - Page metadata is also available via a `p` variable. For example, the page title can be output with: [@""@][!raw!][@ p.title @][!endraw!][@""@] ## File Path Data The `f` variable holds file path data. - `f.dir` - An array with the directories that lead to the file (e.g. `/path/to/something.inc.html` returns `["path", "to"]`. An empty array is returned if the file is at the docroot). - `f.dir_string` - The string to the parent directory (including a leading `/`). - `f.extension` - The final file extension (i.e. `something.inc.html` returns `html`). `NONE` is returned if there's no extension. - TODO: `f.input_extension` - The input file's extension (e.g. `.neo` which would result in an `f.extension` of `.html`). - TODO: `f.input_path` - The array with the path parts to the input file. - TODO: `f.input_path_string` - The string with the path to the input file (includes the leading `/`). - `f.name` - The full file name - `f.stem` - The stem of the file name. (Note that this is everything up to the last `.` which means `something.inc.html` returns `something.inc`). - `f.path` - An array with the output directory and file name (e.g. `/path/to/something.inc.html` returns `["path", "to", "something.inc.html"]. (Use `f.input_path` to get the input file path with the original extension.) - TODO: `f.path_string` - Returns the output path to the file as a string. ## Functions

- TODO: data(path) 

  - Returns the json/toml data for the
    given path by effectively turning 
    `/some/path/file.html` into `j.some.path.file`

- TODO: date(DATE [, FORMAT])

  - Takes an RFC 9557 date and returns
    a string with the date. 

  - The default format is `MONTH, YEAR`.

  - The optional `FORMAT` argument
    can be passed for other formats
    (the formatting is done with 
    standard date formatting tokens).

- exists(PATH)

  - Returns true if the given path exists.

  - Otherwise, returns false. 

  - Expected paths are absolute based
    on the site docroot. 

- files_in_folder(PATH [, EXT])

  - Takes a string that's the path
    to a folder. 

  - Returns an array with the names
    of all the files inside
    the given path. 

  - If the optional `EXT` arguments
    is passed, then only files with
    a matching file extension are
    returned. 


- folders_in_folder(PATH)

  - Takes a string that's the path
    to a folder. 

  - Returns an array with the names
    of all the folders inside
    the given path.

- parent(PATH)

  - Takes a string that's the path to
    a file or directory.

  - Returns a string with the path
    to the parent directory. 

- TODO: parts(PATH)

  - Takes a string that's the path to
    a file or directory.

  - Returns an array of strings
    where each element is a

- stem(PATH)

  - Takes a string that's the path
    to a file or folder. 

  - If the path is a file, then
    the file stem is returned
    (e.g. `/some/path/alfa.txt` returns
    `alfa`)

  - If the path is a folder, then
    the folders basename is returned 
    (i.e. parts of the names after
    dots don't get removed so:
    `/some/path/bravo.inc/` returns
    `bravo.inc`)
