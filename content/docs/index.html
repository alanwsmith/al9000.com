I wrote it in Rust with [MiniJinja](https://docs.rs/minijinja/latest/minijinja/syntax/index.html) providing the horsepower (MiniJinja being the Rust version of [Jinja](https://jinja.palletsprojects.com/en/stable/)). The implementation is based of dozens of prior iterations built over the past several years. The overall goal is to remove as much friction as possible from making web pages. And, not just blog posts, but pages with any given structure or content. The three keys that support that are: 1. All content files are templates with the full range of MiniJinja features available for processing. Each one can output directly or be used as an include in another file. 2. A global `d` variable is available in each template that contains the metadata from every content file as well as the data from every `.json` file on the site. 3. TODO: Images don't require paths. They can be stored anywhere in the content tree and accessed with their filename alone. ## Content Processing - Every file in the content tree can be used as a template that can be processed to generate its output. This allows the use of all MiniJinja logic, filters, and functions inside each content file. - Every file is available to be included in other templates. - Files with `.html`, `.js`, and `.txt` are passed through the transformation engine by default. - TODO: If an `.html`, `.js`, or `.txt` file has `.off` in its file name then it's copied directly without going through the transformation engine. - Files with other extensions are copied without transformation by default. - Files and with `.inc` in their names are available to be included but are not copied to the output tree. - TODO: Neopolitan files (i.e. `.neo` files) pass through the Neopoligen engine then the MiniJinja engine before being sent to the output tree as `.html` files. - TODO: Each file can contain an `id` value defined in its metadata. ## Flags

Flags for customizing aspects of the pages
are defined via a `flags` key in the
TOML block. Individual templates are responsible
for handling behavior changes from 
the flags. Currently, the only flag is:

- no-date - prevent the date from displaying
in the title section of a page. 

- no-title - prevent the title block from
showing up on the page (i.e. the `hgroup` 
element in the default page)

Others will be added as necessary. 

Templates can check for flags like:

[! raw !]


== if "no-date" not in p.flags 
Show date here since no-date is not in the flags.
== endif
