It's gonna change really soon. See the endnote about that. ## One, Two, Three Naming things is one of the two hardest problems in computer science1. I go through half a dozen titles for blog posts. Changes after a page goes live happen more often than not. Blog apps like Wordpress use the title to create a page's address. An entry titled: A Post About Names would be at al9000.com/blog/a-post-about-names Makes sense, unless you change the title. There are a couple options when that happens. You could update the address, but then any links to the old address would break. You can deal with that by setting up the old addresses to bounce visits over to the new one. Or, you could just leave the page at the original address and only update the title on the page itself. You end up with something like a post titled: The Naming of Posts is a Difficult Matter that's still at the address: al9000.com/blog/a-post-about-names Not really a big deal. Page addresses matter much less now than they used to2. I don't like the disconnect, though. ## Shifting Slashes I've been avoiding the issue all together for years by using random characters for addresses3. Something like: al9000.com/blog/01/ng/97/zx/ Purely functional with no regard for aesthetics. The reason for doing: al9000.com/blog/01/ng/97/zx Instead of: al9000.com/blog/01ng97zx is because my site is "static". That means the addresses on the site map directly to folders on my computer (e.g. there is a `blog` folder that has a file named `01ng97zx.html` in it). Lots of apps have problems with folders that have more than a thousand file in them. I've got over three thousand posts. Putting them all in the same folder would bog things down. That's where all the slashes come in. Each one represents a new folder. That is, there's a top level `blog` folder that has a `01` folder in it that has a `ng` folder in it, etc...
