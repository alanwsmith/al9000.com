I use Axum[@ footnote("axum") @] to power a local admin server for this site. It's provides reports on the site's current build state and various CRUD operations to manage content. These tools are Server Side Rendered[@ footnote("ssr") @] using the MiniJinja[@ footnote("mj") @] template engine.

MiniJinja sets up an initial environment before rendering templates. I use axum's `State` to load and store the environment for the admin server when it initializes. Without that, it would have to initialize on every page request.

Here's what the setup looks like:

The `env.set_syntax()` call configures MiniJinja for my preferred setup (e.g. using `[! raw !][@ @][! endraw !]` and the like instead of `{{ }}` for tokens since I find they make the page easier to read. - I also split rending to its own `render` function. Footnotes

== filter md - [@ footref("axum") @] Rust's axum crate provides the HTTP routing and request handling needed to build a web server that hosts dynamic pages. It reminds me a lot of Python's Flask project. - [@ footref("ssr") @] Server Side Rendering is when a server builds the response for each request dynamically when the request arrives. An alternate approach is Static Site Generation which pre-builds all the pages prior to any requests. When one comes in, the server responds with the pre-built payload. It's faster and uses fewer resources and the cost of not being able to customize the responses for each request. (There are, of course, hybrid approaches as well.) - [@ footref("mj") @] MiniJinja is the Rust version of Python's Jinja2 template engine. It provides looping, conditionals, and functions to render pages. It's fantastic. == endfilter
