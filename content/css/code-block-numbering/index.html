For example, this CSS: == filter highlight_block("css") == include f.dir + "/example-1/styles.css" == endfilter and this HTML: == filter highlight_block("html") == include f.dir + "/example-1/code.html" == endfilter Produces this output: == include f.dir + "/example-1/code.html" It works great for basic code blocks that start at 1 and go up uninterrupted from there. ## Start Position Starting with another number is done with the `counter-reset`[@ footnote("reset") @] property. For example, you can start the line numbers at 7 like this: == filter highlight_block("css") == include f.dir + "/example-2/styles.css" == endfilter == filter highlight_block("html") == include f.dir + "/example-2/code.html" == endfilter Which outputs: == include f.dir + "/example-2/code.html" Just remember to reset the counter value to one before the value you want to start with (e.g. 6 gets you 7). ## The Skipping Problem The problem I've been running into is how to show some parts of the code while skipping others. For example, say I've got this code block coming in from an included file: == include f.dir + "/example-3/code.html" But, instead of displaying the entire thing, I only want to show the opening and closing of the `main` function and the `alfa` lines. I could make another copy of the file with the lines removed. That causes two issues: 1. I'd have to duplicate the code. That, in turn requires updating it multiple times for any changes. A pain and entirely too easy to mess up and publish incorrect code. 2. Lines that are removed don't increment the counter. Any lines after a removal end up with different numbers than the original. For example, the closing `}` in this display is marked as line 4 instead of 7: == include f.dir + "/example-3b/code.html" I want to keep the numbers the same for each line: == include f.dir + "/example-3c/code.html" I could use the `counter-reset` approach to set the line number after each removal. It would get complicated fast. Each block would have to be adjusted individually. ## Solution Attributes Enter the CSS `attr()`[@ footnote("attr") @] function. It's been around since 2015 and provides a better way to control line numbering. Specifically, it lets you grab the value from a `data-*` attribute in an HTML element for display. Here's the code that makes it work: == filter highlight_block("css") == include f.dir + "/example-4/styles.css" == endfilter == filter highlight_block("html") == include f.dir + "/example-4/code.html" == endfilter And here's what it looks like: == include f.dir + "/example-4/code.html" The technique requires hard coding the values. The complexity of doing that will vary between systems. It's straight forward with my setup[@ footnote("setup") @]. The hard coding opens up other opportunities as well. Placing an empty line with a dot instead of a number to replace the skipped lines, for example. So, this: == filter highlight_block("html") == include f.dir + "/example-4b/code.html" == endfilter Becomes this: == include f.dir + "/example-4b/code.html" Exactly what I'm looking for. -a
